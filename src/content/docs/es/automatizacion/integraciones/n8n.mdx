## Cómo funciona

n8n se conecta a Cord de dos formas. El **nodo de Cord** (`n8n-nodes-cord`) es el camino corto; el **nodo HTTP Request** sirve para cualquier endpoint de la [API](/docs/desarrolladores/empezar/resumen) que el nodo todavía no cubra.

n8n usa una **llave de API** de Cord, no la autorización de un clic de Zapier y Make: cada instalación de n8n tiene su propia dirección de regreso, y Cord solo acepta direcciones registradas de antemano.

## Con el nodo de Cord

<Steps>
1. En n8n, entra a **Settings › Community nodes** e instala `n8n-nodes-cord`. Necesitas una instalación propia de n8n y ser administrador. En n8n Cloud aparecerá cuando n8n termine de verificarlo.
2. En Cord, ve a **Ajustes**, activa el modo desarrollador al final del índice y abre **API**. Crea una llave con permiso de escritura; las que empiezan con `sk_test_` trabajan contra tu entorno de prueba.
3. En n8n crea una credencial **Cord API** y pega la llave. El botón de probar te dice si es de prueba o de producción.
4. Agrega el nodo **Cord Trigger**, elige los eventos y activa el flujo: n8n registra el webhook en Cord y lo borra cuando lo desactivas.
5. Para actuar sobre Cord, usa el nodo **Cord**.
</Steps>

| Recurso | Operaciones |
|---|---|
| **Clientes** | Crear, actualizar, obtener y buscar. |
| **Cotizaciones** | Crear, obtener, buscar, enviar y marcar pagada. |
| **Tareas** | Crear. |

El disparador verifica la firma `X-Cord-Signature-V1` de cada entrega: un POST que no venga de Cord se descarta.

## Con el nodo HTTP Request

<Steps>
1. En Cord, agrega un webhook en **Ajustes › Modo desarrollador › Webhooks** con la URL del nodo **Webhook** de n8n.
2. Para llamar a la API, usa **HTTP Request** contra `https://cordhq.app/api/v1/...` con el encabezado `Authorization: Bearer sk_...`.
</Steps>

## Límites

Los webhooks y las llamadas de API cuentan contra los límites de tu plan, igual que con Zapier o Make. Los ves en **Ajustes › Modo desarrollador**.

## Desconectar

- **Apagar un flujo:** al desactivar un flujo con **Cord Trigger**, n8n borra en Cord el webhook que había registrado. Si el webhook ya no existía en Cord, n8n se desactiva igual.
- **Cortar el acceso por completo:** revoca la llave en **Ajustes › Modo desarrollador › API**. Desde ese momento n8n ya no puede llamar a la API con ella, y los webhooks que esa llave había registrado dejan de recibir eventos. Borra también la credencial **Cord API** en n8n.
- **Con el nodo HTTP Request:** borra el webhook en **Ajustes › Modo desarrollador › Webhooks**.

## Problemas comunes

| Mensaje o síntoma | Qué hacer |
|---|---|
| **La prueba de la credencial falla** | Pega una llave secreta (`sk_live_` o `sk_test_`). Las llaves publicables (`pk_`) no sirven aquí. Si la llave se revocó, crea otra. |
| **El flujo no se activa con Cord Trigger** | La llave necesita permiso de escritura para registrar el webhook. Revisa también que la dirección de n8n sea `https` y pública: Cord rechaza `http`, `localhost` y direcciones internas o privadas. |
| **"Tus integraciones ya crearon 100 suscripciones, el máximo por organización."** | Desactiva los flujos de n8n, Zaps o escenarios que ya no uses para liberar espacio. |
| **n8n responde 401 a las entregas de Cord** | El disparador rechaza las entregas cuya firma no coincide con el secreto que recibió al registrar el webhook. Desactiva y vuelve a activar el flujo para que registre uno nuevo. |
