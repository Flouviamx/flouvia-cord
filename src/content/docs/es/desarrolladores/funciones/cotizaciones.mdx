## Descripción General

El objeto `Cotizacion` (`quote`) representa una propuesta comercial hacia un cliente. Usando la API de Cord, puedes inyectar cotizaciones directamente desde un ERP, CRM o generar flujos automatizados de carritos de compra.

Todas las cotizaciones generadas vía API quedan registradas en el registro de auditoría (`audit_log`) etiquetadas automáticamente como provenientes de tu Clave de API.

## Crear una Cotización

Para crear un borrador de cotización, debes realizar un `POST /api/v1/cotizaciones` enviando el detalle comercial.

**Petición:**

```bash
curl -X POST "https://cordhq.app/api/v1/cotizaciones" \
     -H "Authorization: Bearer sk_live_tU..." \
     -H "Content-Type: application/json" \
     -d '{
       "cliente_id": "8f7b2c1e-4d3a-4b9f-a6e2-1c5d7e9f0a3b",
       "terminos": "net30",
       "vigencia_dias": 15,
       "notas": "Proyecto anual",
       "base_currency": "EUR",
       "items": [
         {
           "descripcion": "Licencia anual — plan Pro",
           "cantidad": 12,
           "precio_unitario": 500
         }
       ]
     }'
```

Cada línea de `items` requiere `descripcion`, `cantidad` y `precio_unitario`. `producto_id` es opcional (referencia un producto de tu [catálogo](/docs/desarrolladores/funciones/productos) para heredar su nombre y precio de lista) y `precio_negociado` permite capturar un precio con descuento distinto al de lista. No existe un campo `sku`: si quieres enlazar la línea a un producto, usa su `producto_id`.

`base_currency` es la divisa en la que el cliente ve y paga la cotización (ISO 4217, ej. `MXN`, `USD`, `EUR`, `GBP`). Es opcional — si la omites, Cord usa la divisa contable de tu organización — pero la API es agnóstica de país: una cuenta en Madrid, Austin o Bogotá cotiza en su propia divisa sin ningún parámetro adicional.

**Respuesta Exitosa:**

Cord te devuelve el `id` (UUID) de la cotización, su `token` público y el link público (`link_publico`) ya construido como URL absoluta, para que se lo envíes a tu cliente inmediatamente vía WhatsApp, SMS o un motor de correos externo. Si tu organización tiene un dominio propio activo, el link usa ese dominio en lugar de `cordhq.app`.

```json
{
  "data": {
    "id": "2a9d8e4f-6b1c-4d7a-9e3f-5c8b1a2d4e6f",
    "folio": "COT-00104",
    "token": "9f3b6c2a7e1d4f8b0a5c3e7d1b9f2a46",
    "link_publico": "https://cordhq.app/q/9f3b6c2a7e1d4f8b0a5c3e7d1b9f2a46",
    "needs_approval": false
  }
}
```

Si la cotización requiere aprobación interna antes de enviarse (por ejemplo, un descuento fuera de umbral), `needs_approval` viene en `true` y `motivo` describe la razón.

## Listar Cotizaciones

Puedes recuperar tu historial paginado de cotizaciones o filtrar por estado (por ejemplo, buscar todas las cotizaciones `enviadas` o `pagadas`).

**Petición:**

```bash
curl -X GET "https://cordhq.app/api/v1/cotizaciones?status=paid&limit=10" \
     -H "Authorization: Bearer sk_live_tU..."
```

El valor de `status` es el estado interno tal cual (en inglés, no traducido): `draft`, `sent`, `viewed`, `approved`, `rejected`, `expired`, `paid` o `invoiced`. Para buscar una cotización por su folio usa `folio=COT-00104`: compara el folio completo sin distinguir mayúsculas. Para ver solo las de un cliente usa `cliente_id=<uuid>`.

```json
{
  "data": [
    {
      "id": "2a9d8e4f-6b1c-4d7a-9e3f-5c8b1a2d4e6f",
      "folio": "COT-00104",
      "cliente": "Stark Industries",
      "status": "paid",
      "total": 6000,
      "moneda": "MXN",
      "terminos": "Net 30",
      "vigencia": "10 sep 2026",
      "creada": "20 ago 2026",
      "link_publico": "https://cordhq.app/q/9f3b6c2a7e1d4f8b0a5c3e7d1b9f2a46"
    }
  ],
  "meta": { "limit": 10, "offset": 0, "total": 1, "next_cursor": null }
}
```

<Callout type="warning" title="Fechas y términos en formato de presentación">
En la lista y el detalle, `terminos` llega como etiqueta (`Contado`, `Net 30`, `Net 60`) y `vigencia` y `creada` como fechas de presentación (`10 sep 2026`), no como códigos ni fechas ISO. No los parses: para la fecha exacta de cada cambio usa `created_at` del [historial de eventos](/docs/desarrolladores/funciones/eventos) con `object_id`.
</Callout>

En el listado, `link_publico` también es una URL absoluta, igual que en la respuesta de creación. Para el detalle de una sola cotización (líneas, eventos, aprobación), usa `GET /api/v1/cotizaciones/{id}`.

## Proponer líneas con IA

`POST /api/v1/cotizaciones/ia` recibe `{ "texto": "..." }` (el pedido del cliente, hasta 6000 caracteres) y devuelve las líneas emparejadas con tu catálogo, sin crear nada:

```json
{ "data": { "moneda": "MXN", "items": [{ "id": "7e3c9a1f-2b4d-4c6e-8f0a-b1d3e5f7a9c2", "nombre": "Cemento Gris 50kg", "unidad": "saco", "lista": 185, "negociado": null, "cantidad": 5 }] } }
```

`id` es `null` cuando el concepto no está en tu catálogo. Los precios van en `moneda`. Para crear la cotización, manda esas líneas a `POST /api/v1/cotizaciones`. Requiere una llave con escritura y gasta una unidad de IA de tu plan: si ya no quedan, recibes `429` con `code: "ai_quota_exceeded"`; si el texto no trae productos, `422` con `code: "no_items"`.

## Cambiar el estado de una cotización

Con una llave de escritura (`write`) puedes mover la cotización por su ciclo de vida con `POST /api/v1/cotizaciones/{id}`:

```bash
curl -X POST "https://cordhq.app/api/v1/cotizaciones/2a9d8e4f-6b1c-4d7a-9e3f-5c8b1a2d4e6f" \
     -H "Authorization: Bearer sk_live_tU..." \
     -H "Content-Type: application/json" \
     -H "Idempotency-Key: aprobar-COT-00104" \
     -d '{ "action": "approve" }'
```

| `action` | Desde el estado | Resultado |
|---|---|---|
| `send` | `draft` | Envía la cotización al cliente (correo y link). En el plan Gratis consume uno de los envíos del mes. |
| `resend` | `sent`, `viewed`, `expired` | La reenvía al cliente. |
| `approve` | `sent`, `viewed` | La marca como aprobada. |
| `reject` | `sent`, `viewed` | La marca como rechazada. |
| `mark_paid` | `approved`, `invoiced` | Registra el pago. Acepta `payment_method` opcional (por defecto `transferencia`). Los cobros en línea pendientes de esa cotización se cancelan. |

La respuesta es `{ "data": { "ok": true, "status": "approved" } }`. Si la cotización no está en un estado desde el que se pueda aplicar la acción, o si otra petición la cambió al mismo tiempo, recibes `409` con `code: "invalid_state"` y no se aplica nada. Cada cambio queda en el registro de auditoría con tu llave como actor y dispara su evento de [webhook](/docs/desarrolladores/herramientas/webhooks).

Emitir la factura no está disponible por esta ruta: las facturas se crean y emiten con `POST /api/v1/facturas` y `POST /api/v1/facturas/{id}`.

## Eliminar un borrador

`DELETE /api/v1/cotizaciones/{id}` elimina una cotización que **nunca se envió** (`draft`). Cualquier otro estado responde `409`.
