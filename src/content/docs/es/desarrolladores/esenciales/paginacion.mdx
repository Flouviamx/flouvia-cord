## Usa el cursor

Toda lista paginada de la API (`cotizaciones`, `clientes`, `productos`, `facturas` y `events`) devuelve `meta.next_cursor`. Para la página siguiente, repite la petición con `?cursor=<next_cursor>`. Cuando ya no hay más, `next_cursor` llega `null`.

```bash
curl "https://cordhq.app/api/v1/clientes?limit=50" \
     -H "Authorization: Bearer sk_test_…"
```

```json
{
  "data": [
    { "id": "6f1c…", "empresa": "ACME Corp" },
    { "id": "7a2d…", "empresa": "Stark Ind" }
  ],
  "meta": { "limit": 50, "offset": 0, "total": 142, "next_cursor": "WyJTdGFyayBJbmQiLCI3YTJk…" }
}
```

```bash
curl "https://cordhq.app/api/v1/clientes?limit=50&cursor=WyJTdGFyayBJbmQiLCI3YTJk…" \
     -H "Authorization: Bearer sk_test_…"
```

El cursor es un **token opaco**: no lo interpretes ni lo construyas, reenvíalo tal cual. Un cursor que no sea de esa lista responde `400 invalid_cursor`.

## Por qué cursor y no offset

Con `offset`, una cotización que se crea mientras recorres la lista desplaza todo una posición: la página siguiente repite un registro, y si se borra uno, te saltas otro sin enterarte. El cursor apunta a la última fila que viste, así que la siguiente página empieza exactamente después, haya o no escrituras.

Los SDK lo hacen solos: `listAll()` de `@flouviahq/node` siempre pagina por cursor.

```ts
for await (const cliente of cord.clients.listAll()) {
  // todas las páginas, sin repetir ni saltar
}
```

## `limit` y `offset`

- `limit`: resultados por página (1 a 200, 50 por defecto).
- `offset`: sigue funcionando en `cotizaciones`, `clientes` y `productos` por compatibilidad. Si mandas `cursor`, se ignora y `meta.offset` llega `null`.
- `meta.total` cuenta todos los registros del filtro; sirve para mostrar "142 clientes", no para decidir cuándo parar. Para eso usa `next_cursor`.

`facturas` y `events` solo paginan por cursor. Ver [Historial de eventos por API](/docs/desarrolladores/herramientas/webhooks#historial-de-eventos-por-api).
