  <p class="page-subtitle">@flouviahq/node: la API de Cord y la verificación de webhooks desde tu backend, con tu Secret Key.</p>

Cord Elements vive en el navegador; `@flouviahq/node` vive en tu servidor. Es un paquete aparte, sin dependencias, que corre en Node 20+, Bun, Deno, Cloudflare Workers y Vercel. Reemplaza al antiguo `@flouviahq/elements/server`, que sigue funcionando pero ya no recibe cambios.

```bash
npm install @flouviahq/node
```

```ts
import { Cord } from '@flouviahq/node';

const cord = new Cord(process.env.CORD_SECRET_KEY!); // sk_live_…, sk_test_… o una restringida rk_…

const quote = await cord.quotes.create({
  cliente: { empresa: 'Acme', email: 'compras@acme.mx' },
  items: [{ descripcion: 'Instalación', cantidad: 1, precio_unitario: 12500, tax_rate: 0.16 }],
  base_currency: 'MXN',
});
console.log(quote.folio, quote.link_publico);
```

<Callout type="warning">
Una Secret Key vive solo en tu servidor. El SDK se niega a correr en un navegador y la API rechaza una `sk_` que llega desde uno.
</Callout>

## Recursos

`cord.quotes`, `cord.clients`, `cord.products`, `cord.invoices`, `cord.collections`, `cord.events`, `cord.tasks`, `cord.webhookEndpoints`, `cord.elements` y `cord.me`. Las listas se recorren completas con `listAll()`:

```ts
for await (const invoice of cord.invoices.listAll({ estado: 'open' })) {
  // recorre todas las páginas
}
```

## Reintentos sin duplicados

Cada operación que crea o cambia algo lleva una `Idempotency-Key`, la misma en todos sus reintentos: un corte de red nunca crea dos cotizaciones ni registra dos pagos. Los reintentos (red, 429, 5xx) respetan `Retry-After`. Para atar la operación a tu propio identificador:

```ts
await cord.invoices.recordPayment(id, { monto: 5000, moneda: 'MXN' }, { idempotencyKey: `pago-${tuId}` });
```

Los errores son `CordError` con `status`, `code`, `requestId` y `docUrl`.

## Versión de la API

El SDK manda `Cord-Version` con la versión con la que se construyó, así que una actualización de Cord no cambia lo que lees. Para fijar otra: `new Cord(sk, { apiVersion: '2026-10-01' })`. Más en [Versiones de la API](/docs/desarrolladores/esenciales/versiones).

## Webhooks

```ts
import { constructEvent } from '@flouviahq/node';

export async function POST(req: Request) {
  const event = await constructEvent(await req.text(), req.headers, process.env.CORD_WEBHOOK_SECRET!);
  if (event.event === 'invoice.paid') {
    event.data.saldo; // TypeScript sabe que es una factura
  }
  return new Response('ok');
}
```

- Usa el cuerpo **crudo**, nunca uno ya parseado.
- Exige `X-Cord-Signature-V1` con timestamp y 5 minutos de tolerancia: un aviso viejo reenviado se rechaza.
- Durante una rotación de secreto llegan dos firmas; basta con que una cuadre.
- Deduplica por `event.id`: un reintento trae el mismo id.

## Proxy para Cord Elements

Si prefieres no usar una llave publicable en el navegador, tu backend hace de intermediario:

```ts
// app/api/cord/[...path]/route.ts
import { createElementsProxy } from '@flouviahq/node';

const proxy = createElementsProxy({
  secretKey: process.env.CORD_SECRET_KEY!,
  authorizeClients: async (req) => !!(await getSession(req)),
});
export const GET = proxy;
export const POST = proxy;
```

```tsx
<CordProvider proxyUrl="/api/cord">…</CordProvider>
```

El proxy solo atiende la configuración, el catálogo, crear cotizaciones y, si lo autorizas, el directorio de clientes; solo desde tu origen, y sanea la cotización igual que una llave publicable.

## Modo prueba

Con una `sk_test_` puedes provocar lo que en producción hace un tercero, por el mismo código que producción:

```ts
await cord.testHelpers.fiscal.setNextOutcome('pac_caido');
await cord.testHelpers.quotes.view(quoteId);
await cord.testHelpers.webhooks.trigger('invoice.paid');
```

Para recibir los webhooks en tu máquina, usa el [CLI](/docs/desarrolladores/herramientas/cli): `cord listen --forward-to localhost:3000/api/webhooks`.
