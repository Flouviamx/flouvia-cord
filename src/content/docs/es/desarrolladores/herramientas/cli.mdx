## Instalar e iniciar sesión

```bash
npm install -g @flouviahq/cli
cord login
```

`cord login` abre tu navegador con un código de confirmación (por ejemplo `WXYZ-2346`). Revisa que sea el mismo que ves en la terminal y autoriza con tu sesión de Cord: la terminal recibe sola una llave **restringida de prueba** y no tienes que copiar nada.

- La llave solo puede usar los simuladores, leer eventos y proponer configuraciones. No toca datos reales ni aplica nada sin tu aprobación.
- Vence en 90 días y aparece en Desarrolladores › API como `CLI · <tu equipo>`, donde puedes revocarla.
- El código vence en 10 minutos y la llave se entrega una sola vez.
- Sin navegador (un servidor por SSH): `cord login --no-browser` imprime la dirección para abrirla en otro equipo. Para pegar una llave tuya, `cord login --api-key`.

La llave se guarda en `~/.config/cord/config.json` con permisos `0600`. El CLI rechaza cualquier llave en vivo.

## Configurar tu cuenta con IA

```bash
cord setup --sitio tuempresa.com --archivo lista-de-precios.xlsx
```

Sin opciones, `cord setup` te pregunta por tu sitio, a qué se dedica tu negocio y tu lista de precios (`.csv`, `.xlsx`, `.pdf` o foto, hasta 3 MB). Cord lee lo que le des y propone perfil, marca, impuestos, catálogo y plantillas. La propuesta se abre en tu navegador para que la revises: **nada se aplica hasta que la apruebas**, y la terminal te muestra el resultado en cuanto lo haces.

Es el mismo asistente del onboarding y del [servidor MCP](/docs/desarrolladores/herramientas/mcp): una sola propuesta, una sola revisión, sin importar por dónde empieces. La propuesta siempre configura tu cuenta real, aunque la llave sea de prueba.

## Integrar tu proyecto

```bash
cord init
```

Detecta tu framework (Next.js, Astro, Express, Laravel, Django, Flask o FastAPI), te da el comando para instalar el SDK, crea la ruta de webhooks con la firma verificada y escribe tus variables de prueba en un archivo de entorno que git ignora. Nunca sobrescribe un archivo existente.

## Recibir webhooks en tu localhost

```bash
cord listen --forward-to http://localhost:3000/api/webhooks/cord
```

Cord no puede hacer peticiones a tu máquina, así que el CLI abre una sesión en la sandbox. Los eventos pasan por el mismo motor de entrega que en producción (firma, versión de la API, historial) y el CLI los reenvía a tu servidor con los headers de firma reales. Al arrancar imprime el secreto de la sesión: ponlo en `CORD_WEBHOOK_SECRET` y verifica con `constructEvent` igual que en producción.

- Solo reenvía a `localhost`; para otro host usa `--allow-remote`.
- `--events quote.paid,invoice.paid` limita los eventos de la sesión.
- La sesión vence en 24 horas y Ctrl+C la cierra.

## Simular

```bash
cord trigger invoice.paid                 # evento con datos de ejemplo
cord trigger quote.approved --objeto <id> # con los datos reales de una cotización de prueba
cord simulate fiscal pac_caido            # la próxima emisión falla como si el PAC no respondiera
cord simulate quote <id> vencer           # la cotización vence
cord events tail --type quote.paid        # eventos conforme ocurren
```

Son los mismos [simuladores](/docs/desarrolladores/empezar/pruebas) de la API, desde la terminal.
