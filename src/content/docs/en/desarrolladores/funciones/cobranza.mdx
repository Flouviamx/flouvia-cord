## Overview

The Collections API is an analytical, mass-read endpoint specifically designed for recovery workflows. Instead of forcing you to download thousands of quotes and calculate dates manually, Cord performs the complete aging and balance calculations on the backend.

This endpoint is perfect for being consumed by a Cron job (`node-cron` or Github Actions) to trigger SMS reminders, or to feed a PowerBI dashboard.

## Retrieving Portfolio Status

The `GET /api/v1/cobranza` endpoint returns a master summary of the organization's financial health.

<Callout type="info">
**Requires the Professional plan or higher.** Collections is a paid capability. Without the required plan, the endpoint responds `402 Payment Required` with `code: "subscription_required"` instead of data — see [Error Handling](/en/docs/desarrolladores/esenciales/errores).
</Callout>

**Request:**

```bash
curl -X GET "https://cordhq.app/api/v1/cobranza" \
     -H "Authorization: Bearer sk_live_tU..."
```

**Response (Analytical Snapshot):**

The response is structured for immediate use, stripping each account's secret public `token` for security — publishing it in a list would turn any read-only key into a payment-link dispenser. Each `total` is the quote total in its own sale currency, unconverted; the response doesn't include each account's currency. `resumen`, `aging`, and `clientes` add those totals as they are, so if your business quotes in more than one currency those sums mix currencies. The portfolio includes approved or invoiced quotes (`approved`, `invoiced`) that aren't recurring retainers; Cord Invoicing invoices are read with the [Invoices API](/en/docs/desarrolladores/funciones/facturas).


`aging` is an array of 4 fixed buckets, not an object keyed by day range: `vigente` (not yet due), `d30` (1 to 30 days overdue), `d60` (31 to 60), and `d60p` (more than 60). `status` in `items` is the real quote state (`approved` or `invoiced`); when it's overdue, `overdue` comes back `true` and `diasVencido` counts the days.
