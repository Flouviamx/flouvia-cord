## Event history

`GET /api/v1/events` returns your organization's events, newest first. They are the same ones [webhooks](/en/docs/desarrolladores/herramientas/webhooks) deliver: if your server was down, this is where you recover what you missed.

| Parameter | What it does |
|---|---|
| `type` | An event type, for example `quote.approved`. An unknown type responds `400`. |
| `object_id` | The object's id (UUID): the history of one quote or invoice. |
| `limit` | From 1 to 200; defaults to 50. |
| `cursor` | The previous page's `next_cursor`. |

```bash
curl "https://cordhq.app/api/v1/events?type=quote.approved&limit=10" \
     -H "Authorization: Bearer sk_live_tU..."
```

```json
{
  "data": [
    {
      "id": "e81c...",
      "type": "quote.approved",
      "object": "quote",
      "object_id": "2a9d...",
      "data": { "folio": "COT-00104", "total": 6000, "moneda": "MXN" },
      "actor": "client",
      "created_at": "2026-09-20T16:41:07.512Z"
    }
  ],
  "meta": { "next_cursor": "MjAyNi0w..." }
}
```

Pagination is cursor-based and stable: a new event does not shift the page you are reading. It needs a read key.

## Verify a key

`GET /api/v1/me` is the simplest API call: it confirms the key is valid and tells you which organization it belongs to, its permission and its mode.

```bash
curl "https://cordhq.app/api/v1/me" -H "Authorization: Bearer sk_live_tU..."
```

```json
{ "data": { "org": { "id": "6f65...", "nombre": "Aceros del Norte", "plan": "pro" }, "scope": "write", "mode": "live" } }
```

Use it to test a credential before saving it in your integration.
