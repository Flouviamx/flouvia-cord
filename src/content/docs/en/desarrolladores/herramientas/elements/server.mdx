  <p class="page-subtitle">@flouviahq/node: the Cord API and webhook verification from your backend, with your Secret Key.</p>
</header>

Cord Elements lives in the browser; `@flouviahq/node` lives on your server. It is a separate package with no dependencies that runs on Node 20+, Bun, Deno, Cloudflare Workers and Vercel. It replaces the old `@flouviahq/elements/server`, which still works but no longer gets changes.

```bash
npm install @flouviahq/node
```

```ts
import { Cord } from '@flouviahq/node';

const cord = new Cord(process.env.CORD_SECRET_KEY!); // sk_live_…, sk_test_… or a restricted rk_…

const quote = await cord.quotes.create({
  cliente: { empresa: 'Acme', email: 'purchasing@acme.com' },
  items: [{ descripcion: 'Installation', cantidad: 1, precio_unitario: 12500, tax_rate: 0.16 }],
  base_currency: 'MXN',
});
console.log(quote.folio, quote.link_publico);
```

<Callout type="warning">
A Secret Key lives only on your server. The SDK refuses to run in a browser and the API rejects an `sk_` arriving from one.
</Callout>

## Resources

`cord.quotes`, `cord.clients`, `cord.products`, `cord.invoices`, `cord.collections`, `cord.events`, `cord.tasks`, `cord.webhookEndpoints`, `cord.elements` and `cord.me`. Lists are walked in full with `listAll()`:

```ts
for await (const invoice of cord.invoices.listAll({ estado: 'open' })) {
  // walks every page
}
```

## Retries without duplicates

Every operation that creates or changes something carries an `Idempotency-Key`, the same on every retry: a network drop never creates two quotes or records two payments. Retries (network, 429, 5xx) honor `Retry-After`. To tie the operation to your own identifier:

```ts
await cord.invoices.recordPayment(id, { monto: 5000, moneda: 'MXN' }, { idempotencyKey: `payment-${yourId}` });
```

Errors are `CordError` with `status`, `code`, `requestId` and `docUrl`.

## API version

The SDK sends `Cord-Version` with the version it was built with, so a Cord update never changes what you read. To pin another: `new Cord(sk, { apiVersion: '2026-10-01' })`. More in [API versions](/en/docs/desarrolladores/esenciales/versiones).

## Webhooks

```ts
import { constructEvent } from '@flouviahq/node';

export async function POST(req: Request) {
  const event = await constructEvent(await req.text(), req.headers, process.env.CORD_WEBHOOK_SECRET!);
  if (event.event === 'invoice.paid') {
    event.data.saldo; // TypeScript knows it's an invoice
  }
  return new Response('ok');
}
```

- Use the **raw** body, never a parsed one.
- It requires `X-Cord-Signature-V1` with a timestamp and 5 minutes of tolerance: an old event replayed is rejected.
- During a secret rotation two signatures arrive; one matching is enough.
- Deduplicate by `event.id`: a retry carries the same id.

## Proxy for Cord Elements

If you'd rather not use a publishable key in the browser, your backend acts as the intermediary:

```ts
// app/api/cord/[...path]/route.ts
import { createElementsProxy } from '@flouviahq/node';

const proxy = createElementsProxy({
  secretKey: process.env.CORD_SECRET_KEY!,
  authorizeClients: async (req) => !!(await getSession(req)),
});
export const GET = proxy;
export const POST = proxy;
```

```tsx
<CordProvider proxyUrl="/api/cord">…</CordProvider>
```

The proxy only serves the configuration, the catalog, quote creation and, if you authorize it, the client directory; only from your origin, and it sanitizes the quote the same way a publishable key does.

### Give the proxy a restricted key

The proxy doesn't need a Secret Key with every permission. Create a **restricted key** (`rk_`) in Developers › API with only this:

| Resource | Level | What for |
|---|---|---|
| `elements` | write | Configuration and AI line drafting |
| `productos` | read | The Builder's catalog |
| `cotizaciones` | write | Creating the quote |
| `clientes` | read | Only if you use `authorizeClients` |

If your server is compromised, that key can't read invoices, collections or webhooks. You can also pin your server's IPs and give it an expiry. `createElementsProxy` accepts an `rk_` just like an `sk_`.

## Request log

Every API call is recorded in **Developers › Logs**: method, path, status, duration, IP and key. Look up a `CordError`'s `requestId` there to see what Cord received.

## Test mode

With an `sk_test_` you can trigger what a third party does in production, through the same code as production:

```ts
await cord.testHelpers.fiscal.setNextOutcome('pac_caido');
await cord.testHelpers.quotes.view(quoteId);
await cord.testHelpers.webhooks.trigger('invoice.paid');
```

To receive webhooks on your machine, use the [CLI](/en/docs/desarrolladores/herramientas/cli): `cord listen --forward-to localhost:3000/api/webhooks`.
