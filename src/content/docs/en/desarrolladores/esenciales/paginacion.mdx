## Use the cursor

Every paginated API list (`cotizaciones`, `clientes`, `productos`, `facturas` and `events`) returns `meta.next_cursor`. For the next page, repeat the request with `?cursor=<next_cursor>`. When there are no more pages, `next_cursor` is `null`.

```bash
curl "https://cordhq.app/api/v1/clientes?limit=50" \
     -H "Authorization: Bearer sk_test_…"
```

```json
{
  "data": [
    { "id": "6f1c…", "empresa": "ACME Corp" },
    { "id": "7a2d…", "empresa": "Stark Ind" }
  ],
  "meta": { "limit": 50, "offset": 0, "total": 142, "next_cursor": "WyJTdGFyayBJbmQiLCI3YTJk…" }
}
```

```bash
curl "https://cordhq.app/api/v1/clientes?limit=50&cursor=WyJTdGFyayBJbmQiLCI3YTJk…" \
     -H "Authorization: Bearer sk_test_…"
```

The cursor is an **opaque token**: don't parse or build it, send it back as is. A cursor that doesn't belong to that list returns `400 invalid_cursor`.

## Why a cursor and not offset

With `offset`, a quote created while you walk the list shifts everything by one position: the next page repeats a record, and if one is deleted you skip another without noticing. The cursor points to the last row you saw, so the next page starts exactly after it, with or without writes.

The SDKs do it for you: `listAll()` in `@flouviahq/node` always pages by cursor.

```ts
for await (const client of cord.clients.listAll()) {
  // every page, nothing repeated or skipped
}
```

## `limit` and `offset`

- `limit`: results per page (1 to 200, 50 by default).
- `offset`: still works on `cotizaciones`, `clientes` and `productos` for backward compatibility. If you send `cursor`, it's ignored and `meta.offset` is `null`.
- `meta.total` counts every record matching the filter; use it to show "142 clients", not to decide when to stop. Use `next_cursor` for that.

`facturas` and `events` only page by cursor. See [Event history through the API](/en/docs/desarrolladores/herramientas/webhooks#event-history-through-the-api).
