  <p class="page-subtitle">Every time a workflow is triggered, a run records what it did, step by step.</p>

## Where to see them

- In the **workflow list**, each card shows the runs from the last 30 days and, if any, how many failed ("N failed").
- Inside the editor, the **Runs** tab shows the 50 most recent, newest first. Click **Refresh** to load the latest.

Each row shows the status, the event that started it and when it happened. Tap it to see the detail.

<DmWorkflowEditor lang="en" view="runs" />

## Run statuses

| Status | Meaning |
|---|---|
| **Queued** | Created and about to run, or a step failed and it is waiting for its next attempt. |
| **Running** | Running right now. |
| **Waiting** | Reached a wait step. The detail shows "Resumes" with the date. |
| **Completed** | Finished every step it had to run. |
| **Failed** | A step failed on all 3 attempts. The following steps did not run. |
| **Canceled** | Someone canceled it, or the workflow was paused, fell outside the plan or its event stopped existing before it finished. |

## Result of each step

In the detail, every evaluated step shows its result:

| Result | Meaning |
|---|---|
| **Done** | The action completed. |
| **Error** | The action failed. The reason appears below. |
| **Met** | The condition was true and the flow took the "met" branch. |
| **Not met** | The condition was false and the flow took the "not met" branch. |
| **Waiting** | The run reached a wait. |

Steps in the branch that was not taken do not appear, because they did not run.

## Automatic retries

When an action fails, Cord does not give up at the first try:

1. **Immediate retry.** If the failure looks temporary (Slack or HubSpot did not respond, the email did not go out), Cord retries the same step seconds later, without using an attempt.
2. **Another attempt later.** If it still fails, the run goes back to **Queued** and the detail shows "Attempt 1 of 3". The second attempt is scheduled one hour after the first failure, and the third two hours after the second. Cord checks pending runs every hour and also when your account has new activity, so the attempt may run a little after its scheduled time.
3. **Failed.** If the third attempt also fails, the run becomes **Failed** with the last error message.

Errors that do not fix themselves, like "Connect Slack…", skip the immediate retry but still go through the 3 attempts: if you connect Slack in time, the next attempt works.

Every attempt continues **from the step that failed**. Steps already done are not repeated: if the task was created and the Slack message after it failed, the retry only sends the Slack message.

| Attempt | When it runs | Status while it waits |
|---|---|---|
| 1 | When the event happens, with an immediate retry if the failure looks temporary | Running |
| 2 | One hour after the first failure | Queued, "Attempt 1 of 3" |
| 3 | Two hours after the second failure | Queued, "Attempt 2 of 3" |
| No more attempts | The run becomes **Failed** | Failed |

## Retry by hand

On a **Failed** run, click **Retry**. It goes back to **Queued** with attempts reset, continues from the failed step and runs right away. Use it after fixing the cause, for example after reconnecting HubSpot.

Only failed runs can be retried; otherwise you see "Only failed runs can be retried."

<Callout type="warning">
**Retry uses the version the run started with.** It helps when the cause was outside the workflow: a disconnected app, a client without an email or phone, a service that did not respond. If the cause was in the workflow itself (an empty text, a wrong URL, the WhatsApp variables), fix it and publish: the fix applies to new events, and retrying the old run will fail the same way.
</Callout>

## Run it again

There is no button to repeat a run that already finished (**Completed** or **Canceled**): repeating it could send the same email to the client twice or create the same task twice. Depending on what you need:

- **See what it would do with a real event**, without sending anything: use **Test** in the editor. See [Publish, pause and delete](/en/docs/automatizacion/workflows/publicar#test-before-publishing).
- **Make it really run again**: cause the event again, for example by resending the quote. Every new event creates its own run.
- **Recover a failed run**: **Retry**, as explained above.

## Cancel

On a **Queued** or **Waiting** run, click **Cancel**. It becomes **Canceled** and no more steps run. What it already did is not undone.

## Error messages and what to do

Messages appear in your account's language.

### Tasks

| Message | Cause | What to do |
|---|---|---|
| The task title came out empty. | The title only had event data and it arrived empty. | Add fixed text to the title. |
| The task could not be created. | Cord could not save the task. | Click **Retry**. If it persists, write to us. |
| Workflows reached their hourly limit of tasks. | Your workflows created 120 tasks in one hour. | Check whether a workflow triggers more than expected; retry later. |

### Team email

| Message | Cause | What to do |
|---|---|---|
| There is nobody to send the email to. | The account has no owner with an email, or no active members. | Check **Settings › Team & roles** or change **To**. |
| Email is not available right now. | It could not be delivered to anyone. | Cord retries on its own. If it persists, write to contacto@cordhq.app. |
| Workflows reached their hourly limit of emails. | 30 emails in one hour. | Consider Slack or Teams for frequent alerts. |

### Client email

| Message | Cause | What to do |
|---|---|---|
| This event does not carry a quote to act on. | The trigger carries no quote, or the quote no longer exists. | Use a quote or invoice trigger. |
| This event does not carry an invoice to act on. | The event's invoice no longer exists. | Nothing to retry for that document. |
| The client has no email on file. | The document's client has no email. | Add the email to the client and click **Retry**. |
| The message came out empty. | The message only had empty data. | Add fixed text. |
| You reached your plan's sending limit for this month. | The monthly sending quota ran out (5 on the Free plan). | Wait for next month or upgrade. |
| The email to the client could not be sent. | Sending failed. | Cord retries on its own. If it ends Failed, click **Retry**. |
| Workflows reached their hourly limit of emails to clients. | 60 client emails in one hour. | Retry later. |

### WhatsApp

| Message | Cause | What to do |
|---|---|---|
| Connect WhatsApp in Settings › Integrations to use this action. | WhatsApp is not connected. | [Connect WhatsApp](/en/docs/automatizacion/integraciones/whatsapp) and click **Retry**. |
| The client has no phone with a country code on file. | The client has no phone, or it does not start with `+` and the country code. | Edit the client, save the number with `+` and retry. |
| WhatsApp did not accept your template. Check it in Settings › Integrations: it must be approved and have the same number of variables. | The template is not approved, the name does not match, or the number of variables differs. | If the problem is the template, fix it in Meta or in Settings › Integrations and retry. If it is the step's variables, fix them and publish: it applies to new events. |
| WhatsApp did not accept the message. It retries on its own. | A temporary rejection. | Nothing; Cord retries. |
| Workflows reached their hourly limit of WhatsApp messages. | 60 messages in one hour. | Retry later. |

### Slack

| Message | Cause | What to do |
|---|---|---|
| Connect Slack in Settings › Integrations to use this action. | No Slack URL saved. | [Connect Slack](/en/docs/automatizacion/integraciones/slack) and click **Retry**. |
| Slack did not accept the message. Check the connection in Settings › Integrations. | The webhook was deleted or the app was removed from the channel. | Create a new webhook in Slack, paste the URL and retry. |
| The message came out empty. | The message only had empty data. | Add fixed text. |
| Workflows reached their hourly limit of Slack messages. | 120 messages in one hour. | Retry later. |

### Teams

| Message | Cause | What to do |
|---|---|---|
| Connect Microsoft Teams in Settings › Integrations to use this action. | Teams is not connected. | [Connect Teams](/en/docs/automatizacion/integraciones/teams) and click **Retry**. |
| Microsoft no longer accepts the Teams connection. Reconnect it in Settings › Integrations. | With **Connect with Microsoft**, access expired or was revoked. | Click **Reconnect** on the card and retry. |
| Teams did not accept the message. Check that the channel or the flow is still active. | The channel no longer exists, you lost access to it, or the Power Automate flow was turned off or deleted. | Pick another channel or paste a new flow URL, and retry. |
| The message came out empty. | The message only had empty data. | Add fixed text. |
| Workflows reached their hourly limit of Teams messages. | 120 messages in one hour. | Retry later. |

### HubSpot

| Message | Cause | What to do |
|---|---|---|
| HubSpot needs to be reconnected in Settings › Integrations. | Cord's access was revoked. | Click **Reconnect** and retry. |
| HubSpot did not accept this step's data. Check the setup in Settings › Integrations. | HubSpot is not connected or needs reconnecting; the quote or client has not reached HubSpot yet, or the trigger has no quote or client; or the Deal or Company was deleted in HubSpot. | Check the connection. If the record has not arrived, wait; if it ends Failed, check that stages are complete and that the trigger is about a quote or client. |
| HubSpot did not respond. It retries on its own. | A temporary HubSpot failure. | Nothing; Cord retries. |
| The note came out empty. | The note only had empty data. | Add fixed text. |
| Workflows reached their hourly limit of HubSpot notes. | 120 notes in one hour. | Retry later. |

### Send the data to a URL

| Message | Cause | What to do |
|---|---|---|
| The destination URL is not valid or points to an internal server. | The URL is not `https` or not on a public server. | Fix the URL and publish. The fix applies to new events; this run keeps the previous URL. |
| The destination URL did not accept the request. | The destination responded with an error or did not respond in time. | Check the destination; Cord retries within the 3 attempts. |
| Workflows reached their hourly limit of posts to a URL. | 120 posts in one hour. | Retry later. |

### Document actions

| Message | Cause | What to do |
|---|---|---|
| This event does not carry a quote to act on. | **Expire the quote** or **Approve the internal request** with an event that has no quote. | Use a quote trigger. |
| The quote is no longer in a state that allows this action. | When expiring: the quote was already approved, rejected or expired. | Nothing to retry. |
| Your current plan does not include internal approvals. | **Approve the internal request** without approvals in your plan. | Internal approvals require the Scale plan or higher. |
| This quote no longer has a pending approval request. | Someone already decided it or it was withdrawn. | Nothing to retry. |
| This event does not carry an invoice to act on. | **Void the invoice** with an event that has no invoice. | Use an invoice trigger. |
| This invoice cannot be voided: review it in Invoices. | It has payments applied (it needs a credit note) or another rule prevents voiding it. | Review it in **Invoices**. |

### General

| Message | Cause | What to do |
|---|---|---|
| The workflow was paused or deleted before this run finished. | It was paused when the run had to continue. | Nothing; if you wanted it to run, resume before the wait ends. |
| Your current plan does not include this active workflow. | You downgraded and this workflow fell outside the limit. | Pause other workflows or upgrade. See [Limits](/en/docs/automatizacion/workflows/limites). |
| The event that started this run no longer exists. | The event record was removed. | Nothing to do. |
| The workflow went over the allowed number of steps. | The run went past the maximum number of steps. | Split the rule into two workflows. |
| This action is no longer available. | The run used an action Cord retired. | Edit the workflow and publish again. |
| This lookup is no longer available. | The run used a lookup Cord retired. | Edit the workflow and publish again. |
| Internal error while running the action. | An unexpected Cord failure. | It retries on its own. If it ends Failed, click **Retry** or write to us. |

## The health panel

Above the **Workflows** list there is a summary of the last 30 days: how many runs there were, how many completed, how many failed and how many are still running or waiting.

Below it, **Why they failed**: the five most frequent causes, with how many times each one happened, in which workflow it last happened and when. That is the difference between "something is failing" and "Slack disconnected on Tuesday": if one cause has 40 failures and the rest have none, you already know what to fix.

The panel shows up as soon as there are runs. If nothing failed in the period, it says so instead of showing an empty list.
